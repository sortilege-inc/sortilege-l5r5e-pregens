The Source Audit

How faithfully the DSL corpus reproduces each book it was converted from — and how much of that I can actually prove.

What this measures, and what it cannot

The corpus was converted from PDFs by a language model. A model invents confidently, and the existing gates all sit downstream of it: the validator checks that the corpus is well formed, the coverage audit checks that entities exist. Neither compares a word of it back to the page. The 2026-05-20 audit recorded source fidelity as deferred, paused at 3 of 27 schools. This is that comparison, run for the first time.

It uses two references the corpus cannot influence. The compendium independently enumerates what each book contains, which is the basis for completeness. The book's own text is the basis for correctness.

Four limits worth holding onto before reading a single number

  1. A quarter of the rules text cannot be judged this way. The books print success, opportunity and strife as glyphs, and text extraction drops them entirely. Any string carrying that notation is counted as unjudgeable and never as passing. That figure is the ceiling on confidence for each book.
  2. Not verbatim is not the same as wrong. Hand-sampling every book shows most drift is the corpus compressing the book's own sentence — a dropped "such as", a dropped page reference. Meaning usually survives. This page reports drift as drift and does not infer missing mechanics from it.
  3. Completeness is measured on a partial list. The compendium enumerates catalog items — techniques, advantages, schools, titles, gear. It says nothing about systems chapters, tables or procedures, so a book at 100% may still be missing whole sections.
  4. Absent names are mostly the corpus's own filing. Names like "Status 90-99" or "FAQ: NPC Void Points (2020)" were coined by the converter and no book prints them. Outside the Core Rulebook, where they were checked by hand, the absent-name count is not a defect count.

One correction, on the record. An earlier pass of this audit reported that all 28 conditions had lost their removal rules, and that several rules had dropped clauses. Four of those six findings were wrong: the block is REMOVED_WHEN and the search was for Removed When, and the rest compared single strings when the content sat in a sibling block. The method below was changed as a result — it no longer claims content is missing, only that wording differs.
